# BidWise AI — Security Architecture & Verification Report (`VERIFY` Mode)

> **Audit Date:** 2026-10-25  
> **Mode:** `VERIFY` (Server-side code inspected, automated security probes executed, and `Open` findings remediated)  
> **Rule Enforced:** Every security check exists on the server (`backend/src/`). Browser-only checks are not counted as `Done`.

---

## 1. Host and Backend Pattern

* **Primary API & Auth Server (`backend/`):** Stateful Node.js (ESM) + Express `5.2.1` server running on port `4000`, backed by MongoDB via Mongoose `9.9.3`.
* **Forensics & Statutory Verification Microservice (`forensics_verification_service/`):** Stateful Python FastAPI `0.162.0` + OpenCV `5.0.0.93` + PyPDF `6.21.2` service (isolated container/process).
* **Document Storage:** Managed local disk storage (`backend/uploads/`) outside the public static web root. Files are never served via `express.static`; browser access requires a 5-minute HMAC-SHA256 signed URL (`GET /api/v1/files/:token`) verified in constant time via `crypto.timingSafeEqual`.
* **Frontend (`frontend/`):** React `18.3.1` + Vite `4.5.5` SPA (`http://localhost:5173`), communicating with `/api/v1` using Bearer access tokens in memory and `httpOnly` refresh cookies.

## 4. What This Host Cannot Do (and Workarounds)

1. **In-Memory Rate Limiter Across Multi-Node Clusters:**
   * *Limitation:* `express-rate-limit` uses its default in-memory store (`MemoryStore`), which resets on process restart and is not shared across multiple Node.js cluster instances.
   * *Workaround:* Run a single Node.js instance behind a reverse proxy (Nginx / Cloudflare) for the hackathon deployment, or attach `rate-limit-redis` if horizontally scaled.
2. **External Managed Bot Challenge (Cloudflare Turnstile / reCAPTCHA):**
   * *Limitation:* Offline / local Smart India Hackathon evaluation environments may not have external internet access to verify third-party CAPTCHA tokens.
   * *Workaround:* Enforce strict IP-based rate limiting (`authLimiter`: 20 requests per 15 minutes) and account email verification (`isVerified`).
3. **Antivirus / Malware Sandbox Scanning on Uploaded PDFs:**
   * *Limitation:* The local Node.js host does not run a ClamAV daemon.
   * *Workaround:* Enforce strict magic-byte signature validation (`file-type` `fileTypeFromFile`), structural PDF parsing (`pdf-lib`), random UUID storage filenames outside the web root, `X-Content-Type-Options: nosniff` headers, and 5-minute signed streaming tokens.
4. **Python Forensics Microservice Network Isolation:**
   * *Limitation:* `forensics_verification_service/main.py` is an internal microservice running alongside the Node backend.
   * *Workaround:* `allow_origins` is restricted to configured frontend/backend origins (`http://localhost:5173`, `http://localhost:4000`), blocking arbitrary cross-origin requests.
